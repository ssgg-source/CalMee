### 尚未宣称完成的边界

- 自动测试不等于桌面端全部交互回归。真实 WebView 中的说话人绑定、长文稿定位、多窗口编辑和音频切页仍需用户试用；没有拿真实会议做破坏性测试。
- 会中笔记的 localStorage 修订检查不是数据库级原子 CAS；能识别已观察到的旧版本，不能声称完全解决两个进程精确同时写入。真正多写者串行化应后续移至后端事务。
- 普通文档的未保存草稿是当前窗口内存兜底，不是进程崩溃恢复；富文本目前恢复滚动位置，不保证恢复光标选区。
- 后台完成事件已接入资源失效，并去掉部分重复全文刷新；全局任务提示/页面轮询尚未合成单一任务注册表。
- 删除已阻止活跃会议的旧请求复活，但所有非活跃标签与内存草稿的集中清理尚需单独完善；未删除任何旧用户内容。
- 模型安装进度、所有 legacy 动态 invoke 路径并未宣称全部迁移。此次统一的是已列出的公共读写资源及静态调用入口。

- **代码确认**：可以从现有读写调用和组件生命周期直接确认缺口；不代表已经完成桌面端复现。

## 结论

当前不是某个统一刷新函数出错，而是尚无贯穿应用的数据变更约定：

1. 数据库提交后，更新哪些读模型和页面由调用组件自行决定，容易遗漏。
2. 页面内状态、Context、模块级缓存、localStorage、后台任务结果并存，失效方式不一致。
3. `refetch` 有时意味着重新获取数据，有时意味着清空当前状态、卸载工作区并重新加载。
4. 多处异步读取缺少请求代次检查；缓存清空也不能阻止旧请求回来重新写入缓存。
5. 已保存数据、正在编辑的草稿、正在阅读的位置没有彻底分离。

仅增加更多 `refetch()` 或返回页面时全量刷新，会改善一部分旧数据问题，却加剧位置跳动、长文档重载和草稿覆盖风险。

## 当前读写路径清单

以下路径均相对仓库根目录。

| 范围 | 当前持有者 / 刷新方式 | 覆盖情况 |
| --- | --- | --- |

| 智能记录 / 会议纪要 / 会中笔记 | Shell 的 `docText`、文档表、legacy summary、编辑器状态 | 有保存队列和部分请求令牌；仍有回写覆盖与重挂载风险 |

| 日历 | 模块级最多 12 个时间范围缓存 | 无 TTL、无跨页面失效，force 后旧请求仍可回填 |
| 人员 / 词库 | 模块级 `knowledgeSnapshot` | 本页操作会刷新，其他入口创建 / 修改不会失效 |
| 录音页 / 悬浮笔记 | localStorage + DOM 事件 + BroadcastChannel | 已有跨窗口同步，但无会议会话 ID / 单调版本 / 冲突处理 |
| 自定义模型 | 每个 hook 实例单独获取列表；当前配置另有 Context | 本页刷新和部分配置事件可用；列表变更未统一广播 |
| 后台转写 / AI 任务 | 后端事件 + 全局提示监听 + 页面内轮询 | 多处监听同一事件，通知完成不等于文档订阅已更新 |
| 工作区标签与页面定位 | sessionStorage 标签列表 + localStorage 活跃文档标签 | 仅保存部分视图身份，没有完整阅读位置快照 |

## 统一改造约定

### 1. 数据更新，不等于页面重载

建议的数据链路：

`写操作 → 数据库提交 → 返回实体/版本 + 发布变更 → 按资源失效或局部更新 → 活跃视图增量呈现`

数据真值仍是 SQLite / 后端，不增加另一套业务数据库。通知不包含正文、人员名字、API key 或完整配置，只携带受影响资源标识。

建议资源键包括：meeting-list、meeting/{id}、transcripts/{id}/{version}、speakers/{id}、document/{id}/{kind}/{context}、notes/{id}、calendar/{range}、people、hotwords、models/{kind}、job/{id}。

- 当前窗口用共享 store 订阅；跨 Tauri 窗口用统一事件桥。
- 同一命令返回与后端事件应幂等合并，以 revision / operation ID 去重，避免通知风暴。
- 后台任务和导入也必须产生同一数据通知，不能依赖调用页面仍挂载。
- 订阅建立后补一次带版本查询；重新聚焦 / 恢复窗口时轻量复核，弥补丢失事件。
- 优先复用现有 Context 和资源 helper 分步接入；是否引入查询库另行评估。换库本身不能解决数据归属、草稿和跨窗口协议。

### 2. 三种状态分开

- **已保存实体**：后端版本、最后成功快照、更新时间。
- **编辑草稿**：文档 ID、基线版本、当前输入、保存队列、失败状态；不得被后台读结果覆盖。
- **视图状态**：会议 / 标签 / 文稿子版本、筛选、段落锚点、偏移、选区、播放位置；刷新数据不清除它。

为文稿保存 transcriptId / blockId + 相对视口偏移，像素 scrollTop 仅作兜底。段落重新合并时通过源 transcript ID 找到新段落；目标不存在时退到最近时间锚点。音频按 meeting ID + audio identity 保存时间和速度，重新进入时默认暂停，避免意外播放。

### 3. 源内容与 AI 文档的刷新边界

更改讲话人应立即更新原始 / 聚类 / AI 优化文稿的身份显示及后续 AI 输入。**已生成的智能记录 / 会议纪要是可编辑成果，不应自动全文替换其中的人名或重新生成**；记录源版本已变，提供明确的重新生成 / 检查入口。人工修改和旧版保留。

### 4. 分批执行顺序

1. **安全基础**：请求代次、防迟到回包、共享保存队列、dirty 草稿保护；区分初次加载与增量刷新。
2. **会议文档闭环**：说话人统一映射、元数据局部 patch、编辑器稳定实例、文稿锚点与播放器位置恢复。
3. **跨页面闭环**：导入、日历关联、人员 / 词库、模型清单统一失效；迁移现有局部缓存。
4. **后台与跨窗口**：合并任务订阅，主窗 / 笔记条会话版本同步；补观测与清理重复监听。

各批可独立验证和回退；不先大规模重写页面、不用定时全应用刷新、不删除现有数据库或用户测试数据。

## 验收场景

全部自动化使用临时数据库、虚构人员、虚构笔记、受控延迟；实机使用一次性测试会议，不修改真实会议作测试。

1. 已有覆盖名 A → 批量绑定 B，当前页立即显示 B；单条绑定仍严格只影响选定讲话。
2. 160 分钟量级的 fixture，阅读中段保存 / 绑定：锚点不跳，筛选与子版本保留，播放器不重新加载。
3. 原始文稿 → 智能记录 → 返回：恢复各自位置；会议 A → 日历 → 返回 A 同样成立。
4. A 请求故意晚于 B 返回，断言 A 不能写入 B 的实体、正文、summary 或缓存。
5. 清空 / 强制刷新后旧分页回包，不能复活旧记录或污染新页；删除后迟到读不能复活实体。
6. 输入后 100ms 内切页面再返回；延迟写入、失败写入、自动保存关闭分别验证，不能静默丢失内容。
7. 打字期间 summary / AI 任务完成：不覆盖草稿，不抢标签，允许明确接纳新版本。
8. 导入得到 / 旧库 / 保存纯笔记后，首页数量、标签、来源同步，不需重启；批量操作只产生合并刷新。
9. 在会议里关联 / 解绑日历，在设置里同步源删除：首页、日历、会议元数据一致。
10. 在文稿中新建人物 / 添加热词，设置页立即更新；删除后旧选项不继续出现。
11. 两个笔记窗口收到乱序 / 重复 / 上一会话消息，不覆盖新会话；冲突有恢复途径。
12. 获取数据失败保留最后快照，明确显示错误；不能伪装为空列表或保存成功。
13. 建模列表保存 / 删除后，设置与任务选择框一致；默认选择不被无关刷新重置。
14. 记录 invoke 数量、编辑器 mount 次数、音频 load 次数；普通身份修改不能触发全文分页和播放器重建。
